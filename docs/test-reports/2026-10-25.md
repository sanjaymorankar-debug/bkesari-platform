## Test tier

The hub (test.bkesari.com) and LadWani (testladwani.bkesari.com) never
answered within 30 seconds. The Hostinger Business plan had run out of Node.js
processes: the account allows one `listen()` per Node process and caps the
process count, so after the eighth Node site new ones hung or failed with
`spawn EAGAIN`. Both sites now show a static "paused" page and their
auto-deploy is off. This is the main open blocker.

Education (testedu) was tested directly. A hub token was signed with the test
tier's key, which never left the script, and sent to `/dashboard`:

| Case | Expected | Result |
|---|---|---|
| No token | sign-in page | 302 → `/edu/login` ✓ |
| Token signed with a stranger's key | refused | 302 → `/edu/login` ✓ |
| Token for another project (`aud=ladwani`) | refused | 302 → `/edu/login` ✓ |
| Expired token | refused | 302 → `/edu/login` ✓ |
| Valid teacher token | signed in as teacher | 302 → `/edu/dashboard/teacher` ✓ |

The same valid test-tier token sent to **production** Education was refused,
and the production key was refused by testedu, so the tiers cannot sign each
other in.

## Defects found and fixed today

| Area | Defect | Fix |
|---|---|---|
| Hub proxy | `/./ladwani/`, `/x/../ladwani/` and `/ladwani/%2e%2e/edu/` reached a project without its gate (S2) | forward only when the raw and the normalised path both match |
| Hub admin API | ids like `1e400` or `99999999999999999999` gave 500 (S3) | `rowId()` accepts digits only, inside BIGINT |
| Hub PWA | installed phones kept the old menu and styles after a deploy (S3) | service worker is network-first; the cached shell is used only offline |
| Hub | `/ATIP` and `/atip` without the slash leaked the owner-only tab | answered 404 for everyone but the owner |
| Hub | `/edu/` on production showed "not on this tier yet" although Education production was live | tier origins in `portal/proxy.js` (this PR) |
| Hub smoke | `scripts/smoke-dev.sh` treated `/edu/` as public and the owner-only `/atip/` 404 as a warning | probes updated |
| Education on Hostinger | old libpq has no SNI, so Neon refused the connection | endpoint ID passed in the password |
| Education on Hostinger | PHP could not resolve the hub's own hostname to fetch its keys | key set inlined as `HUB_JWKS`; a failed fetch is cached for 60 s |
| Education on Hostinger | Vite manifest not found; seeders timed out | `usePublicPath`; seed data loaded as one SQL batch |
| Education tests | Pint flagged `HubSignInTest`; TESTING.md missed two cases | fixed |
| LadWani on Hostinger | API answered 500: the launcher allows one `listen()` and `fork()` hit `EAGAIN` | API now runs inside the web process |
| Hosting | bkesari.com auto-deploy built with the old Next.js settings and failed | build settings corrected to Express / Node 22 / `portal/start.js`; rebuilt |
| Hub tests | the server.test.js hubs created live routes to the dev sites once tier defaults existed | tests use `APP_ENV=''` and assert every proxy target is local |

## Still open

- **Hosting capacity (blocker).** The Hostinger Business plan runs out of Node.js processes with
  eight Node sites. The dev and test hubs, testladwani and devladwani are paused, and LadWani
  production cannot start. Fix: upgrade to Cloud or a VPS, or delete `devladwani-api`, which is now redundant.
- **LadWani test and production.** Built and passing on dev; [Ladwani#20](https://github.com/sanjaymorankar-debug/Ladwani/pull/20)
  (release to `main`) stays a draft until the test tier passes.
- **Education dev and test** answered 503 on 4 of 24 checks during the run, each time for under a second. This is the plan's PHP process limit.
- **ATIP snapshots.** The Mac uploader needs the new production `ATIP_PUBLISH_TOKEN`; the URL
  `https://bkesari.com/atip/api/snapshot` is unchanged and refuses unauthenticated posts.
- **First production sign-in.** Sign in with agtcipl@gmail.com and confirm the emailed code.
  That also proves Neon Auth email reaches a real inbox (only checked on dev, without a mailbox).
- **Neon Auth production** still allows localhost origins; turn it off in the Neon console.
- **SSH deploy workflows** (`Deploy dev (portal)`, `Deploy dev (edu)`, LadWani `Deploy dev`) fail on
  every push to `dev` because the `DEV_SSH_*` secrets were never set; Hostinger Git deploy is used instead.
- **gokesari.com** (not touched) stopped answering during the run: the CDN gives up after 55 s
  on every request. test.gokesari.com is fine. It needs a restart from hPanel.
