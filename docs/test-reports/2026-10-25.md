## Defects found and fixed today

| Area | Defect | Fix |
|---|---|---|
| Hub proxy | `/./ladwani/`, `/x/../ladwani/` and `/ladwani/%2e%2e/edu/` reached a project without its gate (S2) | forward only when the raw and the normalised path both match |
| Hub admin API | ids like `1e400` or `99999999999999999999` gave 500 (S3) | `rowId()` accepts digits only, inside BIGINT |
| Hub PWA | installed phones kept the old menu and styles after a deploy (S3) | service worker is network-first; the cached shell is used only offline |
| Hub | `/ATIP` and `/atip` without the slash leaked the owner-only tab | answered 404 for everyone but the owner |
| Hub | `/edu/` on production showed "not on this tier yet" although Education production was live | tier origins in `portal/proxy.js` |
| Hub smoke | `scripts/smoke-dev.sh` treated `/edu/` as public and the owner-only `/atip/` 404 as a warning | probes updated |
| Education on Hostinger | old libpq has no SNI, so Neon refused the connection | endpoint ID passed in the password |
| Education on Hostinger | PHP could not resolve the hub's own hostname to fetch its keys | key set inlined as `HUB_JWKS`; a failed fetch is cached for 60 s |
| Education on Hostinger | Vite manifest not found; seeders timed out | `usePublicPath`; seed data loaded as one SQL batch |
| Education tests | Pint flagged `HubSignInTest`; TESTING.md missed two cases | fixed |
| LadWani on Hostinger | API answered 500: the launcher allows one `listen()` and `fork()` hit `EAGAIN` | API ran inside the web process; later moved into the hub |
| LadWani on Hostinger | the plan killed every new Node.js process, so LadWani could not run as its own site | served by the hub: static export plus the API in the hub's process |
| Hosting | bkesari.com auto-deploy built with the old Next.js settings and failed | build settings corrected; rebuilt |
| Hub tests | the server.test.js hubs created live routes to the dev sites once tier defaults existed | tests use `APP_ENV=''` and assert every proxy target is local |
| LadWani in the hub (D1) | a miss under `/ladwani/_next/static/` showed the app's 404 page without the gate | ungated misses get a bare text 404 |
| LadWani in the hub (D2) | no test caught LadWani being mounted after the hub's body parsers, which breaks payment webhooks | the stand-in API keeps the raw body; a test asserts it reaches the API |
| LadWani in the hub (D3) | everyone shared one LadWani rate-limit budget behind the hub | limits count per signed-in person (`X-Bkesari-Visitor`, set by the hub only) |
| LadWani in the hub (D4, D7, D8) | TEST_SPEC.md and DEPLOY.md described LadWani as a proxied site | spec and deploy guide updated |
| LadWani in the hub (D6) | no test pinned the removal of a visitor header sent by the browser | test added |
| LadWani pages | static shells: a page imported a client module, `/ladwani` redirect looped, in-app moves fetched the `_` placeholder | shared constant in its own module, exact-path redirect, route params read from Next's path first |

## Still open

- **First production sign-in.** Sign in with agtcipl@gmail.com and confirm the emailed code.
  That also proves Neon Auth email reaches a real inbox (only checked on dev, without a mailbox).
  Then open https://bkesari.com/ladwani/ to create your LadWani user.
- **Neon Auth production** still allows localhost origins; turn it off in the Neon console.
- **ATIP snapshots.** The Mac uploader needs the new production `ATIP_PUBLISH_TOKEN`; the URL
  `https://bkesari.com/atip/api/snapshot` is unchanged and refuses unauthenticated posts.
- **LadWani D5 (found before this work, in LadWani's own code).** A payment webhook with an
  invalid signature that reuses a stored event id gets a 500. The route is reachable only behind
  the hub's sign-in. A patch is proposed in `.claude/test-runs/20261025-160016-portal-tester.md`.
- **LadWani payment webhooks.** Everything under `/ladwani/` sits behind the hub's sign-in, so a
  real payment gateway could not reach LadWani's webhook. Production uses the built-in dev gateway
  today. Before a real gateway is switched on, its webhook path needs to bypass the gate; its own
  signature check then protects it.
- **LadWani on phones.** The top menu does not wrap. At 390 px it runs past the right edge, so
  the links after "Services" and "Log out" are off screen. The issue is in LadWani's own layout
  (`ladwani/apps/web/src/components/ui.tsx`) and predates the move.
- **LadWani build fonts.** One CI run failed fetching Google Fonts during the build; self-host them
  with `next/font/local`.
- **SSH deploy workflows** (`Deploy dev (portal)`, `Deploy dev (edu)`) fail on every push to `dev`
  because the `DEV_SSH_*` secrets were never set; Hostinger Git deploy is used instead.
- **Education dev and test** answered 503 on 4 of 24 checks during the morning run, each time for
  under a second. This is the plan's PHP process limit.
